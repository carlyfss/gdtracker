**Game event trace auto-create:** When `GameEventIngestService.ingest` saves a `GameEvent`, it inspects the normalized parameters; if both `location` and `map` (lowercase keys in the request, normalized to `LOCATION` / `MAP`) are present and non-blank, it persists a `GameEventTrace` linked to the new event. Failures during the auto-create are logged and do not propagate to the ingest caller.

**Cross-cutting:** `FeatureController` uses `TaskRepository` to enforce rules when deleting features that still have tasks. `CategoryController` uses `TaskRepository.existsByCategoryId` before delete for a clear **category has tasks** conflict. `GameSetupService` creates the default **Game exceptions** category and a `GameConfiguration` row when a game is created or when configuration is first requested and missing (idempotent). `GameAccessService` ensures the authenticated user owns the `gameId` on scoped routes. Request bodies for feature and task upserts use **`dto/`** records with Jakarta Bean Validation; **`ValidationExceptionHandler`** maps validation failures to HTTP 400 with the same style as other `ResponseStatusException` errors. **`ApiLoggingExceptionHandler`** logs `ResponseStatusException` at WARN and other uncaught exceptions at ERROR. **`ApiSecurityLoggingHandlers`** logs 401 entry-point and 403 access-denied (including CSRF) events at WARN.

**Security:** Passwords are stored in **plaintext for local/testing only** (`User.password`, `PlainTextPasswordEncoder`); do not use this configuration in production.
